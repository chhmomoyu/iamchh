两天到半天：用流水线把策划案落到能点、能通协议

笔记

  • 为什么做，效果怎样
    • 初版就把「把策划案丢给 AI」从约 2 天缩短到约半天
    • AI 对需求的理解精准率明显提高
    • 核心不是多写提示词，而是把关卡和模板先写死
  • 它是什么
    • 功能落地总控，只调度，不自己干活
    • 专员各做各的：技术文档、模板拷贝、预制体、配置类型、协议同步、窗口/组件脚本、控制台捕获
    • 禁止一人写完四段，禁止子代理冒充专员
    • 只读可并行，写文件必须串行
  • 先建预制体模板
    • 把反复会出现的东西先做成模板，再拷进具体功能
    • 例如：通用按钮、弹窗、背景，以及后续会沉淀的通用控件
    • 整窗模板必须人确认再拷；拷完不算界面阶段结束
    • 没有专用图时，可用通用资源占位，并记进卡住项
  • 状态怎么记
    • 全程一份 pipeline.json，换会话先读它 + 技术文档，不认聊天
    • 阶段：tech-doc → prefab → scaffold → verify-protocol → done
    • 状态：running / blocked / awaiting-user / done
    • 门：模板已确认、节点名对齐、预制体可见、协议往返
    • done 的唯一条件：协议往返为真
  • 四段（严格串行）
    • 1 技术文档
      • 过关：文档落盘；第四节有全部预制体路径 + 控件表
      • 协议未合、配表没列：只标待确认，不挡住搭界面
      • 「必须先问」未答：停，不准默认实现进第 2 段
    • 2 界面能看见
      • 优先复用已有模板，再改名、对照效果图
      • 文件过关：主窗 + Item 在工程里，节点名对齐，有效果图则对过对照图
      • 对照图只证明工程里能看见，不能代替人看一眼
      • 人过关：刷新后看界面，点头才写脚本；同一轮不准接着写逻辑
    • 3 写完文档主路径
      • 人未点头或节点名未对齐：停或退回第 2 段
      • 写点击、刷新、注册，不是空骨架
      • 要发请求先同步协议；没协议也可先写窗口和注册，只是先不发请求
      • 交互、排序、文案或协议字段对不上：停下来问，不要擅自补一个默认值
      • 能编译、已注册、需求已实现；脚本写完也不算整条流程结束
    • 4 交互 + 协议跑通（全程必做）
      • 人只需：编辑器已刷新、预览已开、已登录能进入口
      • 先环境自检，再抓上行/下行证据
      • 过关：主路径能点，请求发出、回包回来，界面有刷新
      • 缺账号、预览没开或协议没点到：记下来等人处理，不要回头拆前面三步
      • 积分、档位、掉落对不对表，不是这条流水线的结束条件
  • 什么时候该停，什么时候可以继续
    • 该停：还没有策划案、文档没写完整、人还没看过界面、主路径没写完、协议还没跑通
    • 可以继续：协议还没合、配表还没齐、缺专用图可先占位、人还没登录、数值还没对表。这些先记下来，不要让已经做对的步骤作废
  • 几条不能破的约定
    • 整窗模板要等人点头再拷
    • 待确认的问题，不要自己填个默认值接着做
    • 界面刚拼完，同一轮里不要接着写脚本
    • 前面几段不要等登录、等协议才开始
    • 界面能看见，或脚本写完，都不算做完
    • 不要把「数值表对上了」当成整条流程的收尾
